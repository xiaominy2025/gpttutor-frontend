# Provider-blocked Navigator Alpha acceptance harness

Source baseline: reviewed documentation head b232ed50c57d7a0f3e34254fe6b5912d200ed1a5 and integrated runtime 934f2fd837423c45d77082566ba5f55a50df4771. The builder compares the working runtime, conversation protocol, budget, store and canonical master gate blobs against the integrated commit before bundling. This package adds only a harness, its builder, offline tests and this procedure. It does not replace the actual default-OFF installation package.

## Isolation

The acceptance artifact only accepts direct invocations of $LATEST of decisionnavigator-alpha-api in us-east-1, with STAGE=alpha and NAVIGATOR_ENABLED=false. It denies aliases, numbered versions, other functions, and API Gateway events before any dependency access. Input must be a JSON object containing only suite, with one of the three fixed values below. There is no arbitrary request submission. The artifact has no model transport. The only SSM read is the dedicated Navigator HMAC parameter; its value is used in memory to derive a separate acceptance-only signing secret and is never returned or logged. The OpenAI key is never read.

The real DynamoDB adapter targets only fresh NAVIGATOR#acceptance#<run>#<scenario># partitions with sk=STATE and one-hour expiry. The package never writes canonical budget or replay state and does not touch account records. The only read outside the namespace is the same strongly consistent, aliased projection of AI#CONFIG / STATE used by the canonical master gate. It never toggles that record. Injected OFF, missing, malformed, error and timeout cases are clearly synthetic.

## Suites

- protocol: Origin and method denials inside the handler, bootstrap and cookie attributes, signed cookie reuse and forgery, tampered history, caller-bound continuation, replay denial, four-turn closure, a fresh real master read per admitted mock dispatch, and known usage settlement.
- limits: two-per-minute and five-per-visitor daily limits, synthetic per-IP denial and another IP succeeding, cap denial with a seeded synthetic monthly row, a held per-visitor lease, and two held global leases preventing another dispatch. The isolated clock advances minute buckets without waiting on the hosted clock.
- master-and-outcomes: provider-blocked master OFF/missing/malformed/unavailable/timeout cases with zero model charge, followed by a simulated unknown provider outcome with conservative synthetic settlement and replay rejection.

Each invocation returns only suite, pass/fail and a bounded diagnostic label. Keep the direct invocation receipt and the $LATEST revision/CodeSha256 with the acceptance record. No provider request, test decision, cookie, replay token or HMAC material is returned in the receipt.

## Proposed temporary $LATEST execution sequence

1. Install the approved default-OFF template and verify the exact public live alias target and reviewed production ZIP digest. Confirm no alias weight and no integration targeting an unqualified function. Keep the reviewed production ZIP and exact S3 version available for $LATEST restoration. The operator must already have appropriate direct invocation and release permissions, which this harness does not grant.
2. Review the exact harness ZIP digest and temporary-code sequence with the coordinating owner. Read the current $LATEST revision, environment, and CodeSha256. Conditionally install the harness ZIP on $LATEST only, wait for the update to finish, and verify its revision, digest, and unchanged default-OFF configuration. Keep the live alias on the reviewed immutable default-OFF version. Do not publish a test version or change alias weights, routes, roles, stage logs, or public routing. Stop on unexpected drift.
3. Directly invoke $LATEST once for each of the three suites, sequentially, with the exact function ARN and explicit $LATEST qualifier. Collect sanitized receipts and verify the public alias stays pinned. On success or failure, conditionally restore $LATEST to the reviewed production ZIP using the fresh revision and expected harness digest as ownership evidence. If either differs, stop for reconciliation. Wait for completion and verify the restored hash, environment, public default-OFF alias, and unchanged master. Do not delete synthetic rows; the existing TTL expires them.
4. The default-OFF routes should be checked through CloudFront separately. Those HTTP results cannot establish the viewer IP delivered to the runtime. A later nonpublic observer would require a separately reviewed private invocation or confined logging mechanism that can inspect actual CloudFront-originated events without enabling public model transport or logging cookie/decision bodies. The harness uses documentation-range synthetic IPs and no public debug probe. Hosted browser cookie behavior, real viewer-IP attribution and the global master OFF/ON test remain acceptance gaps. Keep master ON; an actual OFF window requires separate owner authorization and coordination with Tree and Process. Do not substitute unverified forwarded headers for source IP. Paid canary and public enablement remain outside this package.

Run locally: node scripts/build-navigator-alpha-acceptance.mjs and npm run test -- --run tests/platform/navigator-alpha-acceptance.test.mjs. The local tests exercise the same suite orchestration with an in-memory optimistic store. They are not evidence of hosted IAM, DynamoDB, browser or CloudFront behavior.
