# Proposed Playbook amendment — AI-light scope

Applies to the November25,2026 v2 proposed consolidated Playbook. This amendment records the superseding owner decision; it does not edit or deploy the external master document. After review, fold it into that single canonical Playbook rather than creating a competing permanent standard.

## Sections1,3,4 and6 — terminology

For Navigator and TypeC Coaches, replace reuse of “AI credentials and accounting” with “secure AI access and abuse protection.” Replace AI-light spending-protection requirements with provider usage monitoring and notifications. Keep analytical facts, factual guards, human judgment, prompts, models, Guest/local workflows and environment isolation unchanged. Decision Tree and Decision Process retain their established policies outside this amendment.

Navigator remains in Explore as a platform/discovery feature, but follows this same nonfinancial AI-light runtime policy. Forecasting, Scenario Analysis and future Simulation/Optimization follow it too.

## Section8 — replacement AI-light integration requirements

AI-light runtimes must reuse secure server-side environment credentials, exact Origin/route checks, signed Guest proof, trusted IP provenance, proportionate visitor/IP request limits, atomic concurrency and replay protection, bounded inputs/outputs, timeouts and a fresh Administrator master gate before paid dispatch. Fail closed when a required security decision cannot be established. Keep no automatic retry after an ambiguous model request.

Do not implement dollar limits, monetary reservations/settlement, financial transaction journals, cost attribution, financial reconciliation or month-based budget initialization in application code. Do not replace them with another accounting service. Missing usage telemetry or unresolved historical financial holds must not become a hidden financial access gate.

Concurrency slots are short-lived execution locks, not spending reservations. Confirmed completion releases a lock; uncertain completion leaves only a bounded lock/replay tombstone. A background monetary reconciliation job is unnecessary. Check lock expiry in code; shared-table TTL is cleanup only.

Use existing OpenAI project usage monitoring and budget notifications. Verify existing project/key mapping, recipient coverage and monitoring-only settings; do not silently change provider organization policies for other applications. A notification threshold is not an application hard cap. No application-wide $10 pool, recurring Coach allowance, trial$1 budget or48-hour pilot window is required for these AI-light Coaches.

Preserve prior financial records as historical evidence without an active runtime dependency. Account for existing TTL during archival; do not alter shared-table TTL or user data to preserve finance history.

## Sections9–11 — lifecycle and acceptance

Use Alpha first and independent Coach releases. Reuse infrastructure; version changed contracts only where compatibility requires it. No new centralized service, dashboard, scheduler or duplicate guard layer without a demonstrated need.

Focus tests on credential isolation, Guest/Origin/IP, request quotas, concurrency/replay, master OFF/unavailable, bounds, timeout recovery and unchanged Coach workflows. Use provider-blocked fixtures before hosted smoke. Reuse prior SSO/MFA/analytical evidence. Paid smoke authorization is bounded by request count and model/input/output limits; do not build durable financial ledgers solely to meter acceptance calls. Respect any explicit narrower owner/tool approval still applicable to a pending diagnostic.

Keep source/artifact identity, conditional alias/HTML ownership and one concise release record. Remove mandatory financial manifests, price calculations, month rollover checks, reservation settlement and cost-reconciliation release stages. Retain prior stopped evidence. Never bypass a tool rejection.

Normal rollback is per-Coach OFF or a compatible known-good quota-only version. Preserve counters/replay state and independent adapter compatibility. Pre-simplification financial versions are historical, not an automatic rollback target that silently reinstates superseded hard spending controls.

## Sections12–14 — ownership and future references

Homepage/Platform owns shared security/abuse contracts and Production coordination. Coach teams own analytical/AI functionality and their adapters. OpenAI usage/notification settings have a designated account owner; no new technical operations dashboard or financial responder role is required.

Replace “approved spending pools” in AI-light standing authorization with “approved provider access and proportionate abuse controls.” Do not interpret that as permission to deploy during a review-only phase, change unrelated applications or bypass explicit paid-test restrictions. Material security/infrastructure changes still require escalation.

Navigator is the reference for signed anonymous conversations and shared discovery UI; Forecasting is the direct-runtime AI-light reference; Scenario illustrates private adapter reuse. Their financial components become historical implementation details, not requirements for future Simulation or Optimization.
